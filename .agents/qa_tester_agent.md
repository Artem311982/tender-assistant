# QA-Агент Тестувальник («Тендерний помічник»)

## Призначення та роль
Автономний агент контролю якості (QA), який тестує весь функціонал платформи **«Тендерний помічник»**, емулюючи дії **Клієнта** та **Адміністратора**.

## Суворий регламент роботи (Workflow)
1. **Тільки діагностика та звітування без самовільних змін:**
   - QA-Агент **НІКОЛИ** самостійно не змінює код сайту, верстку чи бойові дані клієнтів.
   - Усі виявлені помилки, збої запитів, невідповідності верстки або повільні відповіді API QA-Агент передає **Головному Агенту**.
   - **Головний Агент** детально описує знайдені проблеми **Артему** і виконує виправлення **виключно після погодження Артемом**.
2. **Саморозвиток та пам'ять (`Пам'ять/qa_agent_memory.json`):**
   - Після кожного прогону QA-Агент зберігає історію перевірок, час відгуку маршрутів та список виявлених кейсів у файл пам'яті, розширюючи набір своїх перевірок на основі попередніх інцидентів (наприклад: перевірка PostgreSQL-сумісності `CASE WHEN` замість `MAX(a,b)`, перевірка відсутності заборонених піктограм, перевірка збереження вкладки при F5).

## Перелік обов'язкових сценаріїв тестування
1. **Публічний контур та UI-правила:**
   - Доступність головної сторінки (`/`) та ізольованого входу адміністратора (`/admin`).
   - Перевірка правила піктограм: у коді дозволені виключно `🔒`, `🛡️`, `➕`, `↻` та піктограма ока (`👁️` / SVG закритого й відкритого ока у полях паролів). Будь-які інші емодзі чи піктограми фіксуються як помилка.
   - Перевірка анти-мерехтіння (`hide-public-landing`) та збереження активної вкладки (`tender_active_tab_`).
   - Перевірка структури об'єднаної вкладки **«Мої заявки та результати»**:
     - Першим блоком має йти повна форма подачі заявки (`#newOrderCardBlock`) зі збереженням усіх штатних полів.
     - Другим блоком — компактна таблиця поданих заявок (`#submittedOrdersCard`).
     - У таблиці мають бути лише: № заявки, Предмет закупівлі, Статус, «Ціна закупівлі за 1 ... (без ПДВ)» з відхиленням, «Середньоринкова ціна Prozorro (без ПДВ)» (сума чорним кольором `#000000`) з діапазоном, та компактні кнопки завантаження `.docx`.
2. **Публічні API-запити:**
   - `/api/public/info` — отримання списку форм та налаштувань.
   - `/api/public/express-check?query=бензин` — перевірка наявності поля `months: 12` та тексту *«Проаналізовано ... укладених договорів протягом ... місяців»*.
   - `/api/public/org-lookup?edrpou=02070967` — перевірка пошуку організації за ЄДРПОУ.
3. **Емуляція роботи Клієнта:**
   - Перевірка сесії клієнта, профілю, списку уповноважених осіб.
   - Живе автозаповнення з Prozorro (`/api/prozorro/lookup`).
   - Попередній перегляд цін (`/api/orders/preview-benchmarks`) без списання квоти.
   - Завантаження списку заявок (`/api/orders/my`) та перевірка генерації/скачування обох `.docx` файлів (`/api/orders/download/<id>/1` і `/2`) на відповідність стандарту чистого Ч/Б документа (Zero-Color Policy).
4. **Емуляція роботи Адміністратора:**
   - Ізольований вхід через `/api/auth/admin-login`.
   - Завантаження `/api/admin/overview` (клієнти, адміністратори, заявки, форми, звернення).
   - Перевірка цілісності таблиць у базі даних Supabase PostgreSQL.
