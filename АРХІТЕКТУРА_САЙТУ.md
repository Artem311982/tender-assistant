# Візуальна архітектура платформи «Тендерний помічник»

Цей документ містить актуальну архітектуру системи **«Тендерний помічник»** (`https://tender-assistant-y0a5.onrender.com`), включно з інтерфейсами клієнта й адміністратора, маршрутами API, структурою бази даних Supabase PostgreSQL та контуром роботи Агента-Тестувальника (QA).

---

## 1. Загальна системна архітектура (Cloud Infrastructure)


## 3. Структура вкладки «Мої заявки та результати»

| Порядок | Блок | Склад блоку |
| :--- | :--- | :--- |
| **1 (Зверху)** | **Подача заявки за формою** (`#newOrderCardBlock`) | • Вибір затвердженої форми подачі інформації<br/>• Обмін через шаблон Word (`Скачати бланк форми .docx` / `Завантажити заповнений .docx`)<br/>• Живе автозаповнення за ID Prozorro (`UA-...`)<br/>• Усі штатні поля обраної форми у 2 колонки (включно з випадаючим списком класифікатора одиниць виміру Prozorro у полі **«Одиниця виміру»**)<br/>• Кнопки: `Попередній перегляд цін Prozorro`, `Очистити поля`, `Надіслати форму та сформувати Порівняння цін і Обґрунтування` |
| **2 (Знизу)** | **Подані заявки та результати** (`#submittedOrdersCard`) | • Пошук та фільтри (`Усі заявки`, `Готові`, `На перевірці`) + кнопка `↻ Оновити список`<br/>• **Єдина компактна таблиця заявок** (без зайвої висоти рядків):<br/>  1. **№ заявки** (`№ 1`, `№ 2`...)<br/>  2. **Предмет закупівлі** — назва предмета + активне посилання на власне оголошення в Prozorro (якщо зазначено ID або URL)<br/>  3. **Статус** (`Результат надано` / `Очікує погодження`)<br/>  4. **Ціна закупівлі (без ПДВ)** — *«Ціна закупівлі за 1 [од.] (без ПДВ)»* + сума чорним + *«Відхилення від ринку: ...%»*<br/>  5. **Середньоринкова ціна Prozorro (без ПДВ)** — сума чорним + *«Діапазон: мін – макс грн»* + інтерактивне посилання `Джерела Prozorro (N договорів)`, що відкриває модальне вікно з повним переліком підібраних контрактів та прямими посиланнями<br/>  6. **Документи (.docx)** — компактні кнопки `Обґрунтування (.docx)` та `Додаток (.docx)` |

## 4. Схема бази даних Supabase PostgreSQL

```mermaid
erDiagram
    USERS ||--o{ SESSIONS : "має активні сесії"
    USERS ||--o{ ORDERS : "подає заявки"
    USERS ||--o{ FEEDBACK_MESSAGES : "надсилає звернення"
    USERS ||--o{ PASSWORD_RESETS : "відновлює пароль"
    FORMS ||--o{ ORDERS : "визначає шаблон"

    USERS {
        int id PK
        text email UK
        text password_hash
        text full_name
        text org_name
        text edrpou
        text role "admin | user"
        text account_type "admin | client"
        text delivery_override "auto | manual | default"
        int quota "Кількість доступних заявок"
        text permissions_json "Права доступу"
        text authorized_persons_json "Список УО"
    }

    ORDERS {
        int id PK
        int user_id FK
        int form_id FK
        text input_data_json "Вхідні поля заявки"
        text benchmarks_json "Підібрані договори Prozorro"
        text stats_json "Розраховані ціни та відхилення"
        text file1_name "Обґрунтування (.docx)"
        text file2_name "Додаток (.docx)"
        int is_released "1 = відкрито клієнту, 0 = на модерації"
    }

    FORMS {
        int id PK
        text title
        text fields_json
        text docx_template_path
        int is_active
    }

    SETTINGS {
        text key PK
        text value
    }
```

## 5. Контур роботи Агента-Тестувальника (QA Agent)

```mermaid
sequenceDiagram
    participant QA as QA-Агент (Тестувальник)
    participant Site as Сайт / API (Render або Localhost)
    participant MainAgent as Головний Агент (Antigravity)
    participant Artem as Артем (Власник платформи)

    QA->>Site: 1. Перевірка публічних маршрутів та Експрес-перевірки ринку
    QA->>Site: 2. Емуляція Клієнта (Вхід, Профіль, Prozorro Lookup, Прев'ю цін, Таблиця заявок, Скачування .docx)
    QA->>Site: 3. Емуляція Адміністратора (/admin, Клієнти, Модерація, Форми, Звернення)
    QA->>Site: 4. Перевірка правил дизайну (відсутність заборонених піктограм, Ч/Б формат .docx)
    QA->>MainAgent: 5. Звіт про виявлені помилки, неточності або вузькі місця
    MainAgent->>Artem: 6. Чіткий опис виявлених проблем та пропозиція рішення
    Artem->>MainAgent: 7. Погодження виправлення
    MainAgent->>Site: 8. Внесення правок та розгортання
```
